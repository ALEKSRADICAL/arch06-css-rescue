# ADR-001. Управление приоритетами каскада

**Статус:** принято · **Дата:** 17.11.2026

## Контекст

**Какие команды/слои совместно пишут CSS?**
Две команды: Atlas UI (`tokens.css`, `base.css`, `components.css`, `states.css`, `utilities.css`) и подрядчик (`legacy.css`).

**Какие два конкретных конфликта мы видели в DevTools?**
1. `#workbench .ui-button.is-danger` (ID + 2 класса + `!important`, unlayered) перебивал `.ui-button--danger` из слоя `components`. Кнопка «Удалить» получала фон `#a41e24` вместо `var(--color-danger)`.
2. `.ui-field:has(input:invalid) input` (0-2-1, слой `states`) срабатывала сразу на пустом `required`-поле — до взаимодействия пользователя.

## Рассмотренные варианты

| Альтернатива | Плюсы | Риски | Почему выбрали или отклонили |
|---|---|---|---|
| A. Всё в одном CSS-файле | Простота | Нет изоляции legacy, конфликты возвращаются | Отклонено: не решает проблему unlayered-правил |
| B. БЭМ + регламент селекторов | Понятное именование | Не решает порядок каскада и `!important` | Отклонено как единственное решение: БЭМ не управляет каскадом |
| C. `@layer` + токены + контракт компонента | Контроль над каскадом, изоляция legacy, темизация | Требует явного порядка слоёв | Выбрано: даёт предсказуемый каскад и изоляцию |
| D. Только CSS Modules | Локальные имена, изоляция | Не решает проблему глобального legacy; требует смены сборки | Отклонено: избыточно для данной задачи |

## Решение

**Порядок слоёв:**
```css
@layer reset, legacy, tokens, base, components, states, utilities;
Более поздний слой имеет больший приоритет для normal-правил. Для important порядок обратный — поэтому !important запрещён.

Принцип специфичности:
Запрещены #id в селекторах компонентов. Максимальная специфичность компонента — 0-2-0. Состояния — только в слое states.

Публичные классы и модификаторы:

Кнопка: .ui-button, модификаторы --primary, --secondary, --ghost, --danger, --sm, --lg.

Карточка: .ui-card, модификатор --featured, слоты __meta, > .ui-button.

Поля: .ui-field, .ui-field__hint, .ui-field__actions.

Зависимость от селекторов родителя:
Компонент оформляет только свои прямые элементы и слоты (.ui-card > .ui-button, .ui-card__meta), не всех потомков. Запрещено .ui-card p { ... } — ломает вложенные уведомления.

Third party CSS:
Legacy импортируется только в @layer legacy. Селекторы ограничены .legacy-widget (не влияют на .ui-* и глобальные теги).

## Последствия и риски
Что будет при подключении ещё одной команды или библиотеки?
Её CSS должен быть импортирован в отдельный слой (@layer vendor2), иначе перебьёт компоненты. Если библиотека использует !important — потребуется изоляция или отказ от библиотеки.

Как обнаружить регрессию?
npm test (18 структурных проверок) + визуальная проверка на 6 ширинах (320–1920 px) и в двух темах + DevTools → Layers.

Два контрпримера
1. Почему добавление !important не является решением проблемы?
!important меняет порядок слоёв на обратный. Unlayered-правила с !important всё равно побеждают любые слои. В нашем проекте #workbench .ui-button.is-danger { !important } перебивал всё, пока мы не удалили !important и не изолировали legacy.

2. Где одного @layer недостаточно?

!important в legacy: для important порядок обратный, legacy может стать сильнее компонентов.

Глобальные селекторы (button, input): даже в @layer legacy влияют на все элементы. Нужна область .legacy-widget button.

Селекторы с ID (#workbench): высокая специфичность перебивает слои. Нужно убрать ID.
